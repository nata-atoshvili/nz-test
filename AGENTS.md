# Правила разработки LOM AI

## Область проекта

Клиентский учебный чат на React, TypeScript strict, Vite, Zustand и Ant Design.
Сохраняйте небольшой объём тестового задания. Не добавляйте FSD-слои, backend,
собственную UI-библиотеку или обёртки над Ant Design без конкретной задачи.

## Структура и зависимости

- `src/app` — компоновка приложения и провайдеры.
- `src/components/ComponentName` — компонент, его CSS Module и локальные типы.
- `src/hooks/useHookName` — React-поведение, отделённое от отображения.
- `src/agent` — локальные сценарии и генератор событий; без React, store и DOM-хранилища.
- `src/store` — состояние чатов, обработчик событий и адаптер сохранения.
- `src/types` — общие типы чата и протокола агента; без runtime-кода.
- `src/styles` — базовые стили, палитра и тема Ant Design.
- `src/utils` — универсальные функции без React и зависимости от приложения.

Используйте `@/` для импортов между каталогами и `./` внутри одного модуля.
Компоненты не импортируют реализацию агента и не управляют таймерами запросов.
Сценарии не зависят от store. Модуль сохранения не импортирует конкретный store.
Не создавайте пустые каталоги и файлы-посредники без необходимости.

## Код

- После блока импортов в React-компонентах обязательна пустая строка перед остальным кодом.

- Компоненты и их каталоги — PascalCase, хуки и функции — camelCase.
- Имя основного файла соответствует основному экспорту.
- Простые типы оставляйте локально; props и разделяемые локальные типы — в `ComponentName.types.ts`.
- `.d.ts` используйте только для ambient-деклараций и описания внешних модулей.
- Используйте `import type` для типов, `unknown` и проверку данных вместо `any`.
- Один `const` на объявление; обработчики с нетривиальной логикой именуйте `handle...`.
- Комментарии объясняют ограничения и причины решения; не дублируют код.
- Не добавляйте мемоизацию, абстракции и зависимости без практической причины.

## Стили и доступность

- Стили компонента находятся рядом в `ComponentName.module.scss`.
- Имена CSS-классов — БЭМ: `composer`, `composer__input`, `sidebar__chat_active`.
- Каждый оформляемый элемент получает собственный класс, указанный явно в JSX.
- SCSS организуйте одним корневым блоком компонента: БЭМ-элементы вкладывайте через `&__element`,
  модификаторы — внутрь своего элемента через `&_modifier`. Не объявляйте `.block__element` отдельно на верхнем уровне.
  Для псевдоклассов и псевдоэлементов используйте `&:hover`, `&::after`. Вложенность не должна создавать
  зависимость от структуры DOM: без селекторов тегов, потомков, дочерних элементов и внутренних классов Ant Design.
- Брейкпоинты задавайте только в `$grid-breakpoints` в `src/styles/variables.scss`.
  Адаптивные правила размещайте внутри соответствующего класса через
  `@include mixins.media-breakpoint-down(md)` или `media-breakpoint-up(md)`.
  Подключение: `@use '@/styles/mixins';`. Числовые размеры viewport в компонентах запрещены.
- `media-breakpoint-up(md)` действует от 768 px, `media-breakpoint-down(md)` — до 767.98 px.
- Между CSS-блоками оставляйте пустую строку, включая правила внутри media queries.
- Глобальные стили также задавайте через классы; не используйте универсальные reset-селекторы.
- Общие цвета берите из `src/styles/theme.ts` через CSS-переменные; не дублируйте палитру.
- Используйте семантические элементы, доступные имена кнопок и видимый клавиатурный фокус.
- Сохраняйте мобильную адаптацию и поддержку reduced motion.

## Асинхронность

Генерация принадлежит конкретному чату и попытке запроса, а не открытому экрану.
Сохраняйте отмену через AbortController и защиту от запоздавших событий по идентичности контроллера текущей попытки.
Повтор не дублирует вопрос. Удаление отменяет запрос. Перезагрузка помечает незавершённый
ответ как прерванный. Ошибки localStorage не должны ломать чат.

## Форматирование и проверка

Prettier: 4 пробела, одинарные кавычки, точки с запятой, без trailing comma,
ширина строки 120. Конфигурация форматирования — источник истины.

После изменений запускайте `npm run lint`, `npm run format:check`, `npm test`, `npm run build`.
Тесты — небольшой набор Vitest для контекста агента, streaming и управления запросами.
Изменения интерфейса проверяйте вручную в браузере на desktop и мобильной ширине.
Не добавляйте браузерный тестовый стек или моки DOM без необходимости.
Не пишите тесты, повторяющие реализацию; проверяйте пользовательское поведение,
границы данных и асинхронные переходы. Не меняйте внешний вид и UX при рефакторинге.
